# Pixel Lab (نسخهٔ متن‌باز) — بررسی فنی و نقشهٔ راه

سند طراحی برای ساخت یک ویرایشگر «متن روی عکس» بومی اندروید با Kotlin،
هم‌تراز با اپ PixelLab و با اولویت پشتیبانی درست از فارسی.

وضعیت: نقشهٔ راه — هنوز کدی نوشته نشده.

---

## ۱. چرا از صفر می‌سازیم

اپ اصلی «PixelLab – Text on pictures» (پکیج `com.imaginstudio.imagetools.pixellab`،
از App Holdings) یک نرم‌افزار **بستهٔ تجاری** است. هیچ سورس عمومی، ریپازیتوری رسمی،
یا لایسنس متن‌بازی برای آن منتشر نشده و تنها خروجی در دسترس، فایل APK کامپایل‌شده است.
پروژه‌های هم‌نام روی گیت‌هاب (`pixellab-code/*`، `keithkarding/PixelLab`، `PixelLib`)
ارتباطی با این اپ ندارند.

بنابراین «تکمیل کردن سورس اصلی» ممکن نیست. دو گزینه باقی می‌ماند:

| مسیر | ارزیابی |
|---|---|
| دیکامپایل APK و تغییر آن | از نظر حقوقی ناامن (نقض شرایط استفاده و کپی‌رایت)، خروجی smali/obfuscated غیرقابل نگهداری، هر آپدیت اپ اصلی کار را باطل می‌کند. **توصیه نمی‌شود.** |
| پیاده‌سازی مستقل | مالکیت کامل کد، امکان افزودن هر فیچری، بدون محدودیت لایسنس. **مسیر انتخابی.** |

> ⚠️ در طول پیاده‌سازی، هیچ asset ای (فونت، استیکر، آیکون، طرح رابط کاربری) از اپ اصلی
> برداشته نمی‌شود. ایده‌ها و قابلیت‌ها قابل پیاده‌سازی مستقل‌اند؛ دارایی‌های هنری نه.

## ۲. دامنهٔ قابلیت‌ها (استخراج‌شده از اپ اصلی)

فهرست زیر مبنای برنامه‌ریزی است، نه لیست آرزو. هر آیتم در بخش ۶ به فاز تخصیص یافته.

**متن**
- افزودن چند لایه متن، چندخطی، تراز چپ/راست/وسط، فاصلهٔ خط و فاصلهٔ حروف
- پرکنندهٔ متن: رنگ یکدست، گرادیان خطی، گرادیان شعاعی، بافت تصویری
- افکت‌ها: سایه، سایهٔ داخلی، خط دور (stroke)، پس‌زمینه، انعکاس، برجسته (emboss)، ماسک
- متن سه‌بعدی (extrude با کنترل عمق، زاویه و رنگ وجه کناری)
- متن منحنی / دایره‌ای
- پرسپکتیو (نشاندن متن روی تابلو یا صفحه‌نمایش داخل عکس)
- کتابخانهٔ فونت + امکان ایمپورت فونت کاربر

**تصویر و لایه‌های دیگر**
- ایمپورت عکس از گالری به‌عنوان لایه
- استیکر، ایموجی، شکل‌های هندسی
- ابزار قلم (رسم آزاد با اندازه و رنگ)
- پس‌زمینهٔ بوم: رنگ، گرادیان، تصویر
- حذف پس‌زمینه: پرده‌سبز/آبی/سفید + جداسازی سوژه
- افکت‌های تصویر: وینیت، هیو، اشباع، راه‌راه

**پروژه و خروجی**
- ذخیرهٔ پروژهٔ قابل ویرایش
- قالب‌های آماده (میم، پوستر، بنر)
- خروجی PNG / JPG / WebP با انتخاب رزولوشن و گزینهٔ پس‌زمینهٔ شفاف

**افزودهٔ ما (چیزی که در اپ اصلی ضعیف است)**
- پشتیبانی درست از **فارسی و عربی**: اتصال حروف، جهت راست‌به‌چپ، متن دوجهته (فارسی + عدد/انگلیسی)،
  و حفظ شکل‌دهی حروف **حتی وقتی افکت سه‌بعدی یا متن منحنی فعال است**
- مدیریت فونت با پیش‌نمایش نمونهٔ فارسی و فیلتر فونت‌های فاقد گلیف عربی

## ۳. معماری

### ۳.۱ ساختار ماژول‌ها

```
:app                  ← ناوبری، تم، نقطهٔ ورود
:core:model           ← مدل داده و سریال‌سازی (بدون وابستگی به اندروید UI)
:core:render          ← موتور رندر — قلب پروژه
:core:text            ← شکل‌دهی متن، منحنی، افکت‌های متنی
:core:data            ← ذخیره‌سازی پروژه، مدیریت asset، مدیریت فونت
:feature:editor       ← صفحهٔ ویرایشگر، ژست‌ها، پنل‌های ابزار
:feature:projects     ← لیست پروژه‌ها، قالب‌ها
:feature:export       ← رندر نهایی و اشتراک‌گذاری
```

جداسازی `:core:render` از `:feature:editor` سخت‌گیرانه است. موتور رندر نباید هیچ
ارجاعی به ViewModel، Compose یا وضعیت انتخاب لایه داشته باشد — فقط `Project` می‌گیرد
و روی `Canvas` می‌کشد.

### ۳.۲ مدل داده

```kotlin
data class Project(
    val id: ProjectId,
    val canvas: CanvasSpec,          // عرض، ارتفاع، پس‌زمینه
    val layers: List<Layer>,          // ترتیب = ترتیب رسم، ایندکس ۰ پایین‌ترین
)

sealed interface Layer {
    val id: LayerId
    val transform: Transform          // موقعیت، مقیاس، چرخش، پرسپکتیو
    val opacity: Float
    val blendMode: BlendMode
    val visible: Boolean
    val locked: Boolean
}

data class TextLayer(
    …,
    val text: String,
    val font: FontRef,
    val size: Float,
    val fill: Fill,                   // Solid | LinearGradient | RadialGradient | Texture
    val paragraph: ParagraphStyle,    // تراز، فاصلهٔ خط، فاصلهٔ حروف، جهت
    val curve: CurveSpec?,            // شعاع خمش
    val effects: List<TextEffect>,    // ترتیب‌دار — ترتیب روی خروجی اثر دارد
) : Layer
```

سه تصمیم کلیدی:

1. **مدل تماماً immutable.** هر ویرایش یک `Project` جدید می‌سازد. با data class و
   ساختار به‌اشتراک‌گذاشته‌شده، هزینهٔ حافظه ناچیز است و undo/redo تقریباً رایگان به دست می‌آید.
2. **`effects` یک لیست مرتب است، نه چند فیلد بولی.** در اپ اصلی هم ترتیب اعمال افکت‌ها
   روی نتیجه اثر دارد؛ مدل‌سازی آن به‌صورت لیست از ابتدا، بازنویسی سنگین در فاز ۴ را حذف می‌کند.
3. **`FontRef` یک شناسه است، نه `Typeface`.** مدل باید سریال‌پذیر و قابل ذخیره بماند؛
   تبدیل به `Typeface` کار لایهٔ رندر است.

### ۳.۳ موتور رندر — مهم‌ترین قاعدهٔ پروژه

> یک تابع رندر، دو مصرف‌کننده. پیش‌نمایش روی صفحه و خروجی نهایی **باید** از مسیر
> یکسان عبور کنند و فقط در ضریب مقیاس تفاوت داشته باشند.

```kotlin
fun renderProject(canvas: Canvas, project: Project, scale: Float)
```

اگر برای پیش‌نمایش مسیر جداگانه‌ای نوشته شود، خروجی نهایی هرگز دقیقاً شبیه پیش‌نمایش
نمی‌شود — این شایع‌ترین باگ ساختاری در ویرایشگرهای گرافیکی است و بعداً قابل اصلاح نیست
بدون بازنویسی. تمام مقادیر مطلق (ضخامت stroke، آفست سایه، عمق سه‌بعدی) در مختصات بوم
ذخیره و هنگام رسم در `scale` ضرب می‌شوند.

### ۳.۴ رندر متن فارسی — سخت‌ترین بخش فنی

Android به‌صورت داخلی از HarfBuzz برای شکل‌دهی استفاده می‌کند، پس
`Canvas.drawText("سلام")` درست کار می‌کند. مشکل جای دیگری است:

**هر افکتی که حروف را جداگانه جابه‌جا کند، اتصال حروف فارسی را می‌شکند.**

راهکار، به ترتیب اولویت:

| افکت | روش | وضعیت فارسی |
|---|---|---|
| stroke، سایه، سه‌بعدی، انعکاس | رسم **کل رشته** چند بار با آفست/`Paint` متفاوت | ✅ سالم — شکل‌دهی حفظ می‌شود |
| متن منحنی | `Canvas.drawTextOnPath` | ✅ سالم — اندروید خودش شکل‌دهی را انجام می‌دهد |
| پرسپکتیو | `Matrix.setPolyToPoly` روی لایهٔ رندرشده | ✅ سالم — روی بیت‌مپ اعمال می‌شود |
| انیمیشن یا افکت per-glyph | نیازمند موقعیت گلیف‌های شکل‌دهی‌شده | ⚠️ نیازمند `TextRunShaper` + `Canvas.drawGlyphs` (API 31+) |

نتیجهٔ مهم: **اکثریت قاطع افکت‌ها با رسم کل رشته قابل پیاده‌سازی‌اند.** تنها جایی که
باید سراغ گلیف‌های جداگانه رفت، افکت‌های per-character است که در فاز ۴ و فقط برای
API 31+ در نظر گرفته می‌شود، با fallback به رسم یکپارچه در نسخه‌های پایین‌تر.

برای متن دوجهته (مثلاً «قیمت: 250 تومان») از `BidiFormatter` و `StaticLayout` با
`textDirection` صریح استفاده می‌شود، نه محاسبهٔ دستی عرض.

### ۳.۵ نگاشت افکت‌ها به API اندروید

| افکت | پیاده‌سازی |
|---|---|
| رنگ یکدست / گرادیان | `Paint.shader = LinearGradient / RadialGradient` |
| بافت تصویری | `Paint.shader = BitmapShader` |
| خط دور | `Paint.Style.STROKE` + `strokeWidth`، رسم پیش از پرکننده |
| سایه | کپی آفست‌شده با `BlurMaskFilter` (نه `setShadowLayer` — کنترل کمتری دارد) |
| سایهٔ داخلی | `saveLayer` + ماسک متن + `PorterDuff.SRC_ATOP` روی کپی محو و معکوس |
| برجسته | `EmbossMaskFilter` |
| انعکاس | رسم آینه‌ای (`scale(1f, -1f)`) با ماسک آلفای گرادیان |
| پس‌زمینه | `RoundRect` پشت کادر متن با padding قابل تنظیم |
| سه‌بعدی | N کپی با آفست تدریجی در جهت بردار عمق، سپس رسم وجه اصلی روی آن |
| پرسپکتیو | رندر لایه در بیت‌مپ، سپس `Matrix.setPolyToPoly` با ۴ نقطهٔ گوشه |

افکت‌هایی که به ترکیب خارج از صفحه نیاز دارند (سایهٔ داخلی، ماسک، انعکاس) در
`canvas.saveLayer` بسته‌بندی می‌شوند. تعداد `saveLayer`های تودرتو باید محدود بماند —
روی دستگاه‌های ضعیف گران است.

### ۳.۶ ژست‌ها و انتخاب

- یک انگشت: جابه‌جایی لایهٔ انتخاب‌شده؛ روی فضای خالی: پن کردن بوم
- دو انگشت: مقیاس + چرخش هم‌زمان (لنگر روی نقطهٔ میانی)
- ضربه: انتخاب لایه با hit-test از بالاترین لایه به پایین، با اعمال ماتریس معکوس
  روی نقطهٔ لمس و بررسی درون کادر مرزی
- خطوط راهنمای چسبنده در مرکز افقی/عمودی و لبه‌ها، با آستانهٔ چند dp
- هندل‌های گوشه برای تغییر اندازه/چرخش، رسم‌شده در فضای صفحه (نه فضای بوم) تا اندازهٔ
  ثابتی داشته باشند

### ۳.۷ Undo / Redo

با مدل immutable، پشتهٔ محدود (مثلاً ۵۰ حالت) از `Project` نگه داشته می‌شود.
ویرایش‌های پیوسته (کشیدن یک لایه، حرکت اسلایدر) باید **در یک ورودی ادغام شوند** —
در غیر این صورت یک بار کشیدن انگشت، پشته را پر می‌کند. مکانیزم: شروع تراکنش هنگام
`ACTION_DOWN` و ثبت در پشته هنگام `ACTION_UP`.

### ۳.۸ ذخیره‌سازی

فرمت پروژه: فایل `.plab` = آرشیو zip شامل

```
project.json        ← مدل سریال‌شده با kotlinx.serialization
assets/<hash>.png   ← تصاویر ایمپورت‌شده، آدرس‌دهی با هش محتوا
thumbnail.jpg       ← برای لیست پروژه‌ها
```

آدرس‌دهی با هش محتوا یعنی اگر یک عکس در چند لایه استفاده شود، یک بار ذخیره می‌شود.
ایندکس پروژه‌ها در Room نگه داشته می‌شود تا لیست بدون باز کردن فایل‌ها ساخته شود.
فیلد `schemaVersion` از روز اول در `project.json` قرار می‌گیرد تا مهاجرت آینده ممکن باشد.

### ۳.۹ خروجی — ریسک حافظه

خروجی ۴K یعنی بیت‌مپ ARGB_8888 حدود ۳۵ مگابایت، به‌علاوهٔ بافرهای موقت هر `saveLayer`.
اقدامات لازم:

- رندر خروجی روی `Bitmap` نرم‌افزاری (نه canvas سخت‌افزاری) تا محدودیت اندازهٔ بافت GPU دور زده شود
- اگر ابعاد از سقف عبور کرد، **رندر کاشی‌کاری‌شده**: بوم به نوارهای افقی تقسیم و
  هر نوار جداگانه رندر و مستقیم در جریان خروجی نوشته می‌شود
- انجام کار در `WorkManager` یا سرویس foreground برای اینکه چرخش صفحه کار را قطع نکند
- سقف رزولوشن بر اساس حافظهٔ در دسترس دستگاه (`ActivityManager.memoryClass`) پیشنهاد شود

## ۴. پشتهٔ فناوری

| لایه | انتخاب | دلیل |
|---|---|---|
| زبان | Kotlin | خواسته |
| رابط کاربری | Jetpack Compose | پنل‌های ابزار و لیست‌ها سریع‌تر ساخته می‌شوند |
| بوم ویرایشگر | `View` سفارشی با `Canvas`/`Paint` | کنترل کامل روی ماتریس‌ها، hit-test و رسم؛ Compose برای این حجم از رسم دستی مزیتی ندارد |
| وضعیت | ViewModel + `StateFlow` | استاندارد |
| تزریق وابستگی | Hilt | استاندارد اندروید |
| سریال‌سازی | kotlinx.serialization | مدل immutable، بدون reflection |
| پایگاه داده | Room (فقط ایندکس پروژه‌ها) | داده‌های اصلی در فایل می‌مانند |
| بارگذاری تصویر | Coil | یکپارچه با Compose |
| حذف پس‌زمینه | ML Kit Subject Segmentation | روی دستگاه، رایگان، بدون سرور |
| تست | JUnit + Robolectric + تست عکس‌مبنا (screenshot test) روی رندر | رگرسیون بصری تنها راه اطمینان از موتور رندر است |

`minSdk = 26` — پوشش عملی خوب، و از پیچیدگی‌های سازگاری متن در API پایین‌تر جلوگیری می‌کند.
`Canvas.drawGlyphs` (API 31+) فقط در مسیر اختیاری per-glyph استفاده می‌شود.

**فونت‌ها:** فقط فونت‌های با لایسنس آزاد بسته‌بندی می‌شوند. برای فارسی:
Vazirmatn، Sahel، Samim، Estedad، Shabnam (همگی SIL OFL). فونت‌های تجاری ایرانی
(ایران‌سنس و مشابه) بسته‌بندی نمی‌شوند — کاربر می‌تواند خودش ایمپورت کند.

## ۵. تست کردن موتور رندر

موتور رندر بدون تست خودکار، بعد از فاز ۳ غیرقابل تغییر می‌شود. برنامه:

- برای هر افکت، یک پروژهٔ نمونهٔ کوچک به‌صورت JSON در `androidTest/assets`
- رندر آن روی بیت‌مپ ثابت و مقایسه با تصویر مرجع با آستانهٔ تفاوت پیکسلی
- یک مجموعهٔ اختصاصی برای فارسی: اتصال حروف، حروف پایانی، «لا»، اعداد فارسی/لاتین
  در متن راست‌به‌چپ، و همان‌ها با افکت سه‌بعدی و منحنی فعال

این مجموعه از فاز ۱ ساخته می‌شود، نه در انتها.

## ۶. فازبندی

هر فاز باید به یک اپ **قابل استفاده** ختم شود، نه به یک قطعهٔ نیمه‌کاره.

### فاز ۰ — اسکلت
راه‌اندازی پروژه، ماژول‌ها، Hilt، CI (build + test)، تم و ناوبری پایه.
خروجی: اپی که بالا می‌آید و صفحهٔ خالی نشان می‌دهد.

### فاز ۱ — MVP قابل استفاده ⭐
مدل داده، موتور رندر پایه، بوم با پن/زوم، لایهٔ متن با فونت و رنگ یکدست،
ژست‌های جابه‌جایی/مقیاس/چرخش، پس‌زمینهٔ رنگی یا تصویری، خروجی PNG/JPG،
undo/redo، زیرساخت تست رندر.
خروجی: **می‌شود واقعاً متن روی عکس گذاشت و خروجی گرفت.**

### فاز ۲ — افکت‌های متنی
گرادیان و بافت، خط دور، سایه، پس‌زمینهٔ متن، تراز و فاصله‌ها، پنل افکت مرتب‌شدنی.
خروجی: کیفیت تایپوگرافی به سطح قابل رقابت می‌رسد.

### فاز ۳ — لایه‌های دیگر
لایهٔ تصویر، شکل‌ها، استیکر و ایموجی، ابزار قلم، پنل لایه‌ها (ترتیب، قفل، مخفی)،
افکت‌های تصویر (وینیت، هیو، اشباع).
خروجی: ویرایشگر چندلایهٔ کامل.

### فاز ۴ — افکت‌های پیشرفته
متن سه‌بعدی، متن منحنی، پرسپکتیو، انعکاس، برجسته، سایهٔ داخلی، ماسک.
اینجا مسیر per-glyph برای API 31+ بررسی می‌شود.
خروجی: برابری فیچری با اپ اصلی در بخش متن.

### فاز ۵ — پروژه و محتوا
ذخیره/بارگذاری `.plab`، لیست پروژه‌ها با تصویر بندانگشتی، قالب‌های آماده،
حذف پس‌زمینه (کروماکی + ML Kit)، مدیریت و ایمپورت فونت.
خروجی: قابل استفاده برای کار مستمر، نه فقط یک‌بارمصرف.

### فاز ۶ — فارسی و صیقل
مجموعهٔ کامل تست فارسی، اصلاح شکل‌دهی در افکت‌ها، پیش‌نمایش فونت با نمونهٔ فارسی و
فیلتر پوشش گلیف، رابط راست‌به‌چپ، بهینه‌سازی کارایی روی دستگاه ضعیف،
رندر کاشی‌کاری‌شده برای خروجی بزرگ.
خروجی: چیزی که اپ اصلی ندارد.

## ۷. ریسک‌ها

| ریسک | اثر | کاهش |
|---|---|---|
| شکستن اتصال حروف فارسی در افکت‌ها | مستقیماً هدف اصلی پروژه را از بین می‌برد | رسم کل‌رشته به‌عنوان پیش‌فرض؛ مجموعهٔ تست فارسی از فاز ۱ |
| اختلاف پیش‌نمایش و خروجی نهایی | بعداً بدون بازنویسی قابل اصلاح نیست | یک تابع رندر مشترک با پارامتر `scale` — قاعدهٔ غیرقابل نقض |
| OOM هنگام خروجی با رزولوشن بالا | کرش روی دستگاه‌های میان‌رده | بیت‌مپ نرم‌افزاری، رندر کاشی‌کاری‌شده، سقف بر اساس حافظهٔ دستگاه |
| افت فریم با لایه‌های زیاد | ویرایشگر کند و غیرقابل استفاده | کش کردن لایه‌های تغییرنکرده در بیت‌مپ، رندر مجدد فقط لایهٔ فعال هنگام ژست |
| بزرگ شدن دامنه | پروژه هرگز تمام نمی‌شود | هر فاز باید خودش قابل استفاده باشد؛ فاز ۱ کوتاه نگه داشته شود |
| لایسنس فونت | مشکل حقوقی در انتشار | فقط فونت‌های OFL بسته‌بندی شوند |

## ۸. قدم بعدی

با تأیید این سند، فاز ۰ و ۱ شروع می‌شود: ساختار ماژول‌ها، مدل داده، موتور رندر پایه
و بوم قابل استفاده با لایهٔ متن و خروجی — یعنی نقطه‌ای که اپ برای اولین بار واقعاً کار می‌کند.
