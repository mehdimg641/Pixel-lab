# تحقیق فیچرها — کاتالوگ یکپارچهٔ سوپر اپلیکیشن

جمع‌آوری و ادغام قابلیت‌های هشت اپ مرجع، برای ساخت یک ویرایشگر گرافیک شخصی
روی اندروید با اولویت **کاور و متن سه‌بعدی فارسی**.

وضعیت: تحقیق — منتظر تأیید پیش از شروع پیاده‌سازی.

---

## ۰. خلاصهٔ مدیریتی

سه یافتهٔ اصلی که باقی سند را شکل می‌دهند:

**۱. معماری رندر در نقشهٔ راه قبلی برای این دامنه کافی نیست.**
سند قبلی بر پایهٔ `Canvas`/`Paint` اندروید نوشته شده بود. آن معماری برای «متن روی عکس»
درست است، ولی چهار خواستهٔ جدید آن را می‌شکند: حالت‌های ترکیب فتوشاپ، لایه‌های تنظیم
غیرمخرب، فیلترهای زنده، و متن سه‌بعدی واقعی. اینها همه به **پایپ‌لاین GPU با شیدر**
نیاز دارند. جزئیات در بخش ۴.

**۲. «سه‌بعدی» در PixelLab و در Tenada دو چیز کاملاً متفاوت‌اند.**
PixelLab سه‌بعدی جعلی می‌سازد — همان رشته را N بار با آفست می‌کشد (۲.۵ بعدی).
Tenada سه‌بعدی واقعی دارد: چرخش روی محورهای X/Y/Z، متریال، نورپردازی، بافت.
هدف اول شما «جدیدترین متن‌های سه‌بعدی فارسی» است، یعنی مدل Tenada — و آن یک
موتور رندر سه‌بعدی می‌خواهد، نه چند بار `drawText`. این بزرگ‌ترین تصمیم فنی پروژه است.

**۳. دامنه در این ابعاد، یک اپ نیست — یک پلتفرم است.**
«تمام ویژگی‌های فتوشاپ دسکتاپ + Canva + PicsArt + ۵ اپ دیگر» در مقیاس واقعی
چندین نفر-سال کار است. این را یک بار می‌گویم و بعد راه‌حل می‌دهم: راه‌حل، ساختن یک
**هستهٔ درست و کامل** است که تمام آن فیچرها روی آن *افزودنی* باشند، نه بازنویسی.
اگر مدل سند، سیستم ماسک و پایپ‌لاین رندر از روز اول درست باشد، هر فیچر بعدی یک
افزونه است. اگر نباشد، هر فیچر یک بازنویسی است. شما گفتید زمان اصلاحیه ندارید —
پس تمام وزن پروژه باید روی همین هسته برود.

## ۱. هر اپ چه چیز *منحصربه‌فردی* دارد

مرجع‌ها همپوشانی زیادی دارند. این جدول فقط چیزی را نشان می‌دهد که هر اپ **بهتر از بقیه**
انجام می‌دهد — یعنی دلیل وجودش در این لیست:

| اپ | سهم منحصربه‌فرد |
|---|---|
| **PixelLab** | افکت‌های متنی عمیق و کنترل دستی دقیق روی هر پارامتر؛ پنل لایهٔ ساده و سریع؛ کشیدهٔ فارسی |
| **Tenada** | سه‌بعدی **واقعی** (چرخش XYZ، متریال، نور)، ۳۰۰+ پریست حرکتی، خروجی PNG شفاف و ویدیو کروماکی |
| **Canva** | قالب‌های انبوه، برند کیت، تغییر اندازهٔ خودکار طرح بین پلتفرم‌ها، کتابخانهٔ عناصر |
| **Photoshop** | مدل سند حرفه‌ای: ماسک لایه، ماسک برش، لایهٔ تنظیم، اسمارت آبجکت، ۲۷ حالت ترکیب، مسیر برداری |
| **PicsArt** | افکت‌های خلاقانه (دیسپرشن، گلیچ، دریپ)، کتابخانهٔ استیکر عظیم، ابزار نقاشی |
| **Photoroom** | ویرایش دسته‌ای انبوه، جداسازی سوژهٔ بسیار دقیق، قالب‌های محصول‌محور |
| **Hypic** | فیلترهای مولد (کارتون، سبک هنری)، ارتقای کیفیت با AI |
| **AirBrush** | رتوش پرتره در سطح تخصصی: پوست، فرم صورت، چشم، دندان، نور |

PNG شفاف.

## ۴. پیامد معماری — تغییر نسبت به نقشهٔ راه قبلی

این مهم‌ترین بخش سند است.

### چرا `Canvas` اندروید کافی نیست

| خواسته | چرا Canvas شکست می‌خورد |
|---|---|
| ۲۷ حالت ترکیب فتوشاپ | `BlendMode` اندروید فقط زیرمجموعه‌ای دارد؛ بقیه باید شیدر سفارشی باشند |
| لایهٔ تنظیم غیرمخرب | باید در زمان ترکیب محاسبه شود، نه روی پیکسل ثابت شود |
| فیلتر زنده روی لایه | هر تغییر پارامتر یعنی رندر مجدد کل لایه روی CPU — کند |
| متن سه‌بعدی واقعی | Canvas اصلاً سه‌بعدی نیست |
| بوم بزرگ با لایه‌های زیاد | ترکیب روی CPU در ابعاد چاپ، فریم‌ریت را می‌کشد |

### معماری پیشنهادی: هیبرید

```
┌─ لایهٔ برداری/متن ──→ Skia (Canvas) ──→ بافت GPU ─┐
│                                                    │
├─ لایهٔ سه‌بعدی ─────→ Filament (PBR) ──→ بافت GPU ─┤
│                                                    ├──→ ترکیب‌کنندهٔ GPU ──→ خروجی
├─ لایهٔ تصویری ───────────────────────→ بافت GPU ─┤   (شیدر: blend + mask
│                                                    │    + adjustment + filter)
└─ لایهٔ تنظیم ────────→ پارامتر شیدر ──────────────┘
```

- **رستر کردن** متن و وکتور با Skia انجام می‌شود (چون شکل‌دهی فارسی را درست بلد است)
- **ترکیب** همهٔ لایه‌ها روی GPU با شیدر انجام می‌شود (حالت ترکیب، ماسک، تنظیم، فیلتر)
- **لایهٔ سه‌بعدی** با Filament رندر و به‌عنوان یک بافت وارد همان ترکیب‌کننده می‌شود

قاعدهٔ «یک مسیر رندر برای پیش‌نمایش و خروجی» از سند قبلی همچنان برقرار است و حالا
اهمیت بیشتری دارد: تفاوت فقط در رزولوشن بافت هدف است.

### متن سه‌بعدی فارسی — مسیر فنی

این دقیقاً همان چیزی است که Tenada انجام می‌دهد و PixelLab نمی‌تواند:

```
متن فارسی
   ↓ Skia/HarfBuzz — شکل‌دهی و اتصال حروف
Paint.getTextPath() → مسیر برداری کل رشتهٔ شکل‌دهی‌شده
   ↓ تقریب منحنی‌ها به چندضلعی
   ↓ مثلث‌بندی (tessellation)
وجه جلو (mesh دوبعدی)
   ↓ اکسترود در محور Z + تولید دیوارهٔ کناری + محاسبهٔ نرمال
mesh سه‌بعدی
   ↓ Filament — متریال PBR، نور، سایه، بافت، محیط
رندر سه‌بعدی واقعی با چرخش آزاد X/Y/Z
```

نکتهٔ کلیدی: `getTextPath` مسیر **کل رشتهٔ شکل‌دهی‌شده** را می‌دهد، نه حرف‌به‌حرف.
یعنی اتصال حروف فارسی از قبل انجام شده و در هندسهٔ سه‌بعدی حفظ می‌شود. این همان
جایی است که پیاده‌سازی‌های ساده‌انگارانه شکست می‌خورند.

### PSD

- **خواندن:** `pixelprobe` از مخزن `platform/tools/base` گوگل — پارسر PSD به زبان جاوا،
  لایسنس Apache 2.0، قابل استفاده و توسعه. مبنای ایمپورت لایه‌دار.
- **نوشتن:** انکودر اختصاصی برای زیرمجموعه‌ای که پشتیبانی می‌کنیم.
- Aspose.PSD تجاری و گران است — استفاده نمی‌کنیم.

موتور متن با شکل‌دهی درست، کشیده، افکت‌های کامل، مدیر فونت، **متن سه‌بعدی با Filament**.
اینجا اپ برای کار روزانهٔ شما قابل استفاده می‌شود.

**موج ۳ — کاور و دارایی**
قالب‌های کاور، اندازه‌های شبکه‌های اجتماعی، شکل‌ها، استیکر، برند کیت، برش دلخواه.

**موج ۴ — قدرت فتوشاپی**
لایهٔ تنظیم، Curves/Levels، فیلترها، ابزار ترمیم، جداسازی سوژه، ایمپورت PSD.

**موج ۵ — رتوش و AI محلی**
رتوش پرتره، حذف شیء، ارتقای کیفیت.

**موج ۶ — AI ابری**
اتصال API برای تولید تصویر، پرکردن مولد، و بقیهٔ موارد بخش K.

| **دستگاه هدف** | ✅ Realme GT3 240W | اسنپدراگون ۸+ نسل ۱، GPU آدرینو ۷۳۰، تا ۱۶ گیگ رم LPDDR5X، اندروید ۱۳→۱۴. |

### پیامد دستگاه هدف

سخت‌افزار رده‌بالاست و هیچ محدودیتی بر معماری تحمیل نمی‌کند:

- **Vulkan 1.3 و OpenGL ES 3.2** هر دو در دسترس — Filament با بک‌اند Vulkan اجرا می‌شود
- **آدرینو ۷۳۰** برای ترکیب شیدری و رندر سه‌بعدی بلادرنگ کاملاً کافی است
- **۱۲–۱۶ گیگ رم** یعنی بوم‌های بزرگ بدون رندر کاشی‌کاری‌شده هم ممکن‌اند
  (ولی مسیر کاشی‌کاری همچنان پیاده می‌شود، چون سقف اندازهٔ بافت GPU مستقل از رم است)
- **`minSdk = 26`** تأیید شد — هم `Typeface.Builder` با تنظیمات محور فونت متغیر را دارد،
  هم پوشش دستگاه معقولی می‌دهد

### تغییر در بخش B — کشیده

تحلیل فونت‌ها یک قابلیت پیش‌بینی‌نشده را ممکن کرد: شش فونت شما **محور کشیده
(`KASH`/`kash`)** به‌عنوان محور فونت متغیر دارند. یعنی کشیده به‌جای درج کاراکتر تطویل،
یک اسلایدر پیوستهٔ ۰ تا ۱۰۰ می‌شود. جزئیات در بخش ۲ سند فونت‌ها.

همچنین شش تایپ‌فیس **مجموعه‌های سبکی** (`ss01`–`ss03`، `salt`) دارند — شکل‌های
جایگزین حروف که هیچ اپ موبایلی در اختیار کاربر نمی‌گذارد. به فهرست فیچرهای P0 اضافه شد.
